# myAIEdu 아키텍처 규칙

이 규칙은 myAIEdu 프로젝트의 모든 코드 작성과 수정에 적용됩니다. 규칙과 다른 코드를 만들기 전에 먼저 이 문서를 확인하세요.

## 0. 현재 상태 (마이그레이션 전)

목표 구조는 `src/back`, `src/front`입니다. 그러나 현재 실제 코드는 `backend/`, `frontend/`에 있습니다 (마이그레이션은 승인 대기 중).

- **마이그레이션 전:** 신규 코드는 `backend/`, `frontend/`에 작성하되, 아래 **내부 구조와 의존성 규칙(2, 3, 4절)은 지금부터 그대로 지킵니다.**
- **마이그레이션 후:** 경로를 `src/back/`, `src/front/`로 바꾸고 이 문서의 경로 표기도 함께 고칩니다.
- 마이그레이션 없이 `src/` 폴더를 임의로 만들지 않습니다.

## 1. 디렉터리 구조

```
myAIEdu/
├── README.md
├── .claude/rules/architecture.md   ← 이 문서
├── backend/  (목표: src/back/)
│   ├── app/
│   │   ├── main.py        # 조립만: 앱 생성, 미들웨어, 라우터 등록
│   │   ├── core/          # 설정, DB 연결, 공통 오류, 보안 의존성
│   │   ├── models/        # ORM 테이블 정의 (SQLAlchemy)
│   │   ├── schemas/       # 요청·응답 형식 (Pydantic)
│   │   ├── services/      # 비즈니스 규칙
│   │   └── routers/       # HTTP 엔드포인트
│   ├── scripts/           # 일회성 작업 (시드 데이터 등)
│   └── tests/             # pytest
└── frontend/ (목표: src/front/)
    ├── index.html
    ├── css/
    └── js/
        ├── app.js         # 과정·커리큘럼 조회, 입력 검사, API 호출
        └── dashboard.js   # API 문서 & 실습 대시보드
```

## 2. 백엔드 계층과 의존 방향

의존은 **한 방향으로만** 흐릅니다.

```
routers → services → models
   ↓          ↓
 schemas   core (config, database, errors)
```

| 계층 | 해야 할 일 | 하지 말아야 할 일 |
|---|---|---|
| `routers/` | 요청 받기, 서비스 호출, 응답 반환, 상태 코드 지정 | 규칙 판단(정원, 중복 등), 직접 DB 쿼리 |
| `services/` | 비즈니스 규칙, 트랜잭션(commit) | HTTP 객체 사용, 요청 스키마(`schemas/`) import |
| `models/` | ORM 테이블과 관계 정의 | 비즈니스 로직 |
| `schemas/` | 입출력 검증과 형식 정의 | DB 접근 |
| `core/` | 설정, 세션, 공통 예외, 보안 | 기능별 로직 |

**예외 처리 규칙**
- 서비스는 `core/errors.py`의 `AppError` 계열(`NotFoundError`, `ConflictError`, `AuthError`)만 던집니다.
- HTTP 상태 코드로의 변환은 `main.py`에 등록한 핸들러가 담당합니다. 서비스나 라우터에서 `HTTPException`을 직접 던지지 않습니다.

## 3. 백엔드 코딩 규칙

- **서비스가 받는 인자:** 스키마 객체 대신 평범한 값(`name`, `phone`)이나 ORM 객체를 받는 것을 목표로 합니다. 신규 서비스 함수는 이 기준을 따릅니다.
- **설정값:** 환경 변수는 `core/config.py`에서만 읽습니다. 다른 곳에서 `os.getenv`를 직접 호출하지 않습니다.
- **비밀 값:** 관리자 키 등 비밀 값을 코드나 테스트 파일에 하드코딩하지 않습니다. 테스트 전용 값은 `tests/conftest.py`에서만 설정합니다.
- **관리자 전용 API:** 반드시 `core/security.py`의 `require_admin`을 `dependencies=[Depends(require_admin)]`으로 붙입니다.
- **개인정보:** 전화번호는 숫자만 저장합니다. 개인정보 동의 없이 수강생을 저장하지 않습니다.
- **DB 변경:** 테이블 구조를 바꿀 때는 기존 `data/app.db`와 호환되는지 먼저 확인합니다. 파괴적인 변경은 사용자 승인을 받습니다.
- **트랜잭션:** `commit`은 서비스에서만 호출합니다.
- **시드 데이터:** `scripts/`의 시드 스크립트는 여러 번 실행해도 중복이 생기지 않아야 합니다.

## 4. 프론트엔드 코딩 규칙

- 프레임워크 없이 HTML, CSS, 바닐라 JS로 작성합니다. 새 라이브러리를 추가하려면 사용자 승인을 받습니다.
- **API 호출:** 모든 백엔드 호출은 `js/app.js`의 `postJson` 같은 공통 함수를 거칩니다. 화면 코드에 `fetch`를 흩뿌리지 않습니다.
- **API 주소:** `API_BASE`는 `app.js` 상단 한 곳에서만 정의합니다.
- **동적 텍스트:** 서버나 데이터에서 온 값을 HTML에 넣을 때는 반드시 `escapeHtml`을 거칩니다.
- **화면 규칙:** 기본 글자 크기 17px 이상, 버튼 최소 높이 48px, 모바일 기준 16px 좌우 여백을 유지합니다. 가로 스크롤을 만들지 않습니다.
- **사용자 문구:** 모든 화면 문구와 오류 메시지는 한국어입니다.
- **중복 데이터 금지:** 커리큘럼처럼 서버가 가진 데이터를 프론트에 복사해 두면 불일치가 생깁니다. 새로 추가하는 화면 데이터는 가능하면 API에서 받습니다.

## 5. 공통 규칙

- 한국어 주석과 한국어 사용자 메시지를 씁니다.
- 파일 하나에는 한 가지 책임만 둡니다. 한 파일이 80줄을 넘으면 분리를 검토합니다.
- 새 기능에는 테스트를 함께 작성합니다. 정원, 중복, 권한 같은 규칙은 테스트가 반드시 있어야 합니다.
- 기존 테스트가 깨진 상태로 작업을 끝내지 않습니다.
- 확정되지 않은 값(수강료, 정원, 커리큘럼 문장)은 코드에서 `[확인 필요]` 주석으로 표시합니다.

## 6. 변경 후 체크리스트

1. `backend/`에서 `py -m pytest`가 전부 통과하는지 확인
2. 새 파일이 위 구조의 올바른 계층에 있는지 확인
3. 계층 의존 방향을 어기지 않았는지 확인 (`routers`에서 DB 쿼리, `services`에서 `schemas` import 등)
4. 프론트를 바꿨다면 브라우저에서 커리큘럼과 신청 폼을 확인
5. 마이그레이션 여부가 바뀌었다면 이 문서 0절과 경로 표기를 함께 갱신

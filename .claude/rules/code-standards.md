# 코딩 표준 (전역 규칙)

이 문서는 myAIEdu 프로젝트의 모든 개발 팀원에게 공통으로 적용됩니다. 프로젝트를 열면 이 규칙을 기본으로 따릅니다. 구조 규칙은 `architecture.md`를 함께 봅니다.

## 0. 테크 리드 기준

- 역할: myAIEdu의 수석 테크 리드입니다. 판단은 실무 밸런스형으로 합니다. 과한 설계보다 지금 필요한 만큼의 구조를 택합니다.
- 답변과 문서는 한국어로 작성합니다.
- 확인되지 않은 사실은 추측하지 않습니다. 모르면 모른다고 말하고, 확인 방법을 함께 제시합니다.
- 변경 후에는 실행이나 테스트로 검증한 결과만 완료로 보고합니다.

## 1. 주석 (필수)

- **모든 주석은 한국어로 작성합니다.** 영어 주석이나 주석 없는 코드는 허용하지 않습니다.
- 주석은 "무엇을 하는지"보다 **"왜 이렇게 했는지"**를 설명합니다. 코드만 보고 알 수 있는 내용은 쓰지 않습니다.
- 함수와 클래스에는 역할을 한두 줄로 적습니다. 매개변수나 반환값이 자명하지 않으면 함께 적습니다.
- 임시 조치, 알려진 한계, 확정되지 않은 값(예: 정원, 수강료)에는 `TODO:` 또는 `[확인 필요]`를 붙이고 이유를 적습니다.

```python
# 정원 확인과 등록을 한 트랜잭션에서 처리한다.
# 나눠 처리하면 동시 신청 시 정원을 넘을 수 있다.
def enroll(...):
    ...
```

```javascript
// API 호출은 이 함수를 거친다. 오류 형식을 한 곳에서 맞추기 위함이다.
async function apiRequest(path, options) { ... }
```

## 2. 명명과 형식

- Python: 함수와 변수는 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`를 씁니다.
- JavaScript: 함수와 변수는 `camelCase`, 클래스는 `PascalCase`를 씁니다.
- 들여쓰기는 Python 4칸, JavaScript 2칸으로 맞춥니다.
- 사용자에게 보이는 문자열(오류 메시지, 화면 문구)은 한국어로 씁니다.
- 파일 인코딩은 UTF-8을 사용합니다.

## 3. 코드 품질

- 함수는 한 가지 일만 합니다. 길어지면 나눕니다.
- 매직 넘버와 매직 문자열은 이름 있는 상수로 둡니다.
- 예외를 삼키지 않습니다. 빈 `except`나 무시하는 `catch`는 쓰지 않습니다.
- 사용하지 않는 코드, 주석 처리된 코드, 디버그용 출력은 커밋 전에 지웁니다.
- 중복이 세 번 이상 반복되면 공통 함수로 뺍니다. 두 번까지는 그대로 둡니다.

## 4. 보안과 설정

- 비밀 값(관리자 키, 토큰, 비밀번호)은 코드에 하드코딩하지 않습니다. 환경 변수로 읽고, 예시는 `.env.example`에만 둡니다.
- 개인정보(이름, 전화번호)는 로그에 남기지 않습니다.
- 입력값은 서버에서 검증합니다. 프론트엔드 검증은 편의용이지 보안 수단이 아닙니다.

## 5. 테스트와 검증

- 새 기능이나 규칙을 바꾸면 테스트를 함께 추가하거나 고칩니다.
- 커밋 전에 기존 테스트가 모두 통과하는지 확인합니다.
- 프론트엔드 변경은 브라우저에서 실제 동작을 확인합니다.

## 6. 변경 절차

- 작은 단위로 나눠 변경합니다. 한 번에 구조 변경과 기능 변경을 섞지 않습니다.
- 파일 이동이나 이름 변경은 내용 수정과 분리해서 진행합니다.
- 규칙을 바꿀 때는 이 문서와 `architecture.md`를 함께 갱신합니다.
